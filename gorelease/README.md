# gorelease

Go port of `extract/gen_release_plan.py`, for environments where only a Go
binary can be run (e.g. a Windows AVD with no Python available).

Generates the same two release-plan documents (condensed + detailed) from
an `export.json`, byte-for-byte identical in content to the Python
generator's output (verified against `environments/gmx/dev/export.json` —
the only intentional difference is the "Generated by" attribution line).

## Usage

```
gorelease environments/<domain>/<env>/export.json
```

Writes, alongside the input file:

- `release-plan.md`
- `release-plan-detailed.md`

Domain/environment names are inferred from the conventional
`environments/<domain>/<env>/export.json` path shape (same as the Python
script); if the path doesn't match that shape, both fall back to
`<domain>`/`<env>` placeholders in the output, same as the Python version.

## Building

Native build (run on the target OS, or cross-compile):

```
go build -o gorelease .
```

Cross-compile a Windows binary from Linux/macOS:

```
GOOS=windows GOARCH=amd64 go build -o gorelease.exe .
```

No external dependencies — standard library only (`encoding/json`,
`regexp`, etc.), so the build is a single static binary with nothing else
to ship or install on the target machine.

## Files

- `main.go` — CLI entry point, path/domain/env inference, file I/O.
- `types.go` — Go structs mirroring the `export.json` schema.
- `helpers.go` — small formatting/parsing helpers (Oracle/SQL Server URL
  parsing, driver lookup tables, `pyInt`/`pyStr` which render an absent
  optional field as the literal string `"None"`, matching Python's
  `"%s" % None`).
- `analysis.go` — environment-derived facts shared by both documents
  (target-name set, external store dependencies, untargeted SAF agents,
  etc.) — direct port of the analysis functions in `gen_release_plan.py`.
- `render_condensed.go` — `release-plan.md` (procedure once + data
  tables).
- `render_detailed.go` — `release-plan-detailed.md` (every object spelled
  out as its own checklist).

## Keeping this in sync with the Python generator

If `extract/gen_release_plan.py` changes (new object type, wording change,
schema addition), port the same change here — this file is not
auto-generated from the Python source, it's a hand-maintained parallel
implementation. Re-run the parity check below after any change to either
generator.

## Parity check

```bash
# From the repo root:
python3 extract/gen_release_plan.py environments/gmx/dev/export.json
cp environments/gmx/dev/release-plan.md /tmp/py-condensed.md
cp environments/gmx/dev/release-plan-detailed.md /tmp/py-detailed.md
git checkout -- environments/gmx/dev/release-plan.md environments/gmx/dev/release-plan-detailed.md

cd gorelease && go build -o gorelease . && cd ..
gorelease/gorelease environments/gmx/dev/export.json
diff /tmp/py-condensed.md environments/gmx/dev/release-plan.md
diff /tmp/py-detailed.md environments/gmx/dev/release-plan-detailed.md
git checkout -- environments/gmx/dev/release-plan.md environments/gmx/dev/release-plan-detailed.md
```

Only the "Generated by" line should differ.
